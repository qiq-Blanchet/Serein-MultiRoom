# M5 数据导入与备份隔离（第一阶段）

> 状态：2026-11-10，开发分支 `feature/multi-room`；使用原版 Serein 导入/导出 API 和两套独立的合成数据库进行测试。**未操作真实 VPS、原版 main 或用户的私人库，也未完成真实双房端到端部署验收。**

## 用户操作（原版 Dashboard）

进入某间 AI 房间后，该 Dashboard 的「对话导入」「旧记忆库迁移」与「本地叙事卷材料上传」都只指向这间房间的原版 Serein 后端。切换房间后，页面重新载入相应数据。

- 在「旧库迁移」页可选 **完整记忆数据库（SQLite）**，其内容由原版 `/v1/export/backup` 的 SQLite 在线快照生成；包含该房间的 Scene、Event、日记、梦境、心绪、备忘和数据库内任务状态，也包含数据库内保存的模型提供商凭据。它不复制其他房间的资料。
- 同页可选 **Scene＋Event、仅 Scene、仅 Event** 三种**可读 Markdown ZIP**；完全沿用原版 Scene/Event 阅读和过滤规则，只增加服务端种类筛选，未修改原文。这是阅读／整理导出，**不是可以一键导回的完整数据库备份**。
- 多房间下载文件名会包含从**已签名验证的服务器房间上下文**获得的房间 ID（例如 `serein-xiaogi-main-backup.db` 和 `serein-xiaogi-main-scene.zip`），避免多个 AI 的下载文件重名。单房原版文件名和原有存储不变。
- 「对话与 Operit 记忆导入」和「旧记忆库迁移」均显示当前房间 ID，操作调用原版 API，由当前房间自己的 SQLite、后台任务与导入队列处理。原版导入预览、确认、摘要、暂停/继续流程保持不变。
- **跨标签页保护**：网页首次加载时从服务器获取目标房间 UUID。上传、预览、确认、继续处理和导出时，向后端携带这个 UUID 的一个核对头 `X-Serein-Target-Room`。服务器只使用已验证的 cookie/房间路由确定实际数据库；若头部与实际当前房间不符（例如旧标签页 A 仍试图上传、用户在另一标签页已切到 B），直接返回 **409**，要求刷新页面。**这个核对头不负责认证、不允许由客户端指定房间**。没有开启多房间时不施加这一额外要求。
- 此外，「个人记录导入」和「叙事卷本地材料上传」也使用同样的当前房间核对。对于每次正常读写，既有房间网关鉴权和独立 backendFor/request context 保持不变。

## 备份格式与恢复边界

`serein-<room-id>-backup.db` 是完整**数据库**备份，不是整套**房间安装包**：图片/附件文件、独立索引文件、`config.toml`、Docker 编排、独立 Gateway Key、网页管理员登录凭据等不包含在内。因此不能单凭一份数据库文件保证完全恢复整个房间；需要另外备份每房间文件目录和控制层密钥。

**本阶段没有开放「上传 SQLite 并覆盖当前房间数据库」的按钮。** 原版「旧库迁移」接受规定的 Ombre 历史资料备份，不等于支持把新版本 `serein-backup.db` 直接当成恢复文件。后续全房间备份/恢复需要包含**明确的原房间 ID、文件清单、校验和、隔离的预览与确认步骤**；恢复前必须锁定目标房间、验证备份来自哪个 AI、保留原库备份，并保证失败时可回滚。绝不因用户只在 Dashboard 切换了房间就自动恢复到别的库。

## 自动回归

- `tests/test_room_import_export.py`：用 A/B 独立 SQLite 生成完整备份、Scene/Event 分类别 ZIP，验证 A 文件中完全没有 B 的私人数据；数据库备份通过 SQLite quick_check。
- `web/tests/room-import-export.test.mjs`：模拟带服务器签名的房间上下文，验证正确房间通过、跨标签页旧请求/缺失头/错误头直接 409，下载文件名从已验证路由取得。
- 原有 `web/tests/backup-download.test.mjs` 继续验证原版流式数据库下载、只在服务端使用内部密钥及故障处理；Python/Node CI 和 Vite 生产构建持续运行。

## 尚需继续

1. 真实 VPS 上双房并行导入、关闭／刷新／切换后的队列恢复与后台摘要调用验收。
2. 逐房间的**全房间安装包**（包括配置、附件和密钥）以及多房间整体归档的受控生成、下载、恢复预览、校验和与回滚流程；敏感备份默认应被私密保存，不得当成普通无密钥的 ZIP。
3. 进一步按日记、梦境、心绪、备忘等类别提供非破坏性结构化导出，但不要把它们和原版可读 Scene/Event ZIP 混同。
4. 备份的定时管理、保留策略、恢复演练、跨版本升级与回滚。

**原则：不修改原版单房功能/数据挂载；能通过现有房间级数据库和 API 完成的事，不再造重复的记忆库。**
